# Diff and restore (Phase 8)

`pocketgit diff` compares indexed files with working files; untracked files are not included. `diff --staged` compares HEAD's committed snapshot with the index. Staged additions work before the first commit. Both forms are read-only, report file additions/deletions and executable-mode changes, and render unified hunks with three context lines. Missing final newlines are explicit. The domain edit script preserves CRLF and exact final-newline state. Human-readable output escapes control characters (other than tabs) as `\uXXXX`, including carriage returns and terminal escape sequences; it is inspection output, not a byte-preserving patch transport. Binary content (NUL or invalid UTF-8) prints a short difference message without dumping bytes.

`DiffEngine` implements longest common subsequence, trims common prefixes/suffixes, and emits deterministic removals before additions on ties. Text inputs are bounded to 8 MiB and 100,000 lines per side before allocating decoded text or line records. Its changed-region matrix is a flat array bounded at 4,000,000 cells; comparisons beyond these bounds fail clearly. Flat storage avoids millions of tiny row allocations for asymmetric edits. Whole working files use the 64 MiB object payload limit. This is an intentionally bounded MVP, not an unbounded diff for arbitrary-sized text. No external diff or Git program is invoked.

`pocketgit restore FILE` replaces the explicitly named working file from the index. `restore --commit COMMIT FILE` restores that file from a full ID or unique lowercase prefix. These commands deliberately discard the named file's unstaged edits. They do not change the index, HEAD, refs, or reflog. Missing parents are created; byte contents and executable distinction are preserved. A file missing from the selected source is an error, not a deletion request.

Restore resolves paths from the invocation directory, rejects parent-traversal components, paths outside the repository, metadata, symlinks, directories, and non-directory ancestors. It supports one file per command; recursive directory restore and staged restore are not exposed. It coordinates with other writers through index/commit locks, verifies source objects before edits, uses atomic replacement, and attempts ordinary-failure rollback through the shared working-tree editor. Checkout's concurrency and crash limitations also apply.
